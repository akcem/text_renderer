# Text Renderer 项目运行逻辑详解

本文档基于 `main.py` 和核心配置文件 (`config.py`)，总结 `text-renderer` 库生成合成文本图像的完整执行流程和技术原理。

## 一、 项目运行的整体架构：生产者-消费者模型

`text-renderer` 采用 **多进程并发** 的 **生产者-消费者模型** 来实现高性能、大规模的图像生成。

| 角色 | 组件 | 并发模型 | 职责 |
| :--- | :--- | :--- | :--- |
| **生产者** | `multiprocessing.Pool` (进程池) | **多进程并行** | 负责图像的计算密集型生成任务 (`generate_img`)。 |
| **消费者**| `DBWriterProcess` (独立进程) | **单进程串行** | 负责生成的图像的 I/O 密集型存储任务 (`run`)。 |
| **缓冲区**| `multiprocessing.Queue` (`data_queue`) | **进程间通信** | 协调生产者和消费者之间的速度差异，实现解耦和内存优化。 |

---

## 二、 启动与配置加载阶段

### 1. 命令行启动 (`parse_args`)

主程序通过 `argparse` 解析命令行参数，如 `--config` (配置文件路径)、`--num_processes` (进程数) 和 `--dataset` (输出类型：`lmdb` 或 `img`)。

### 2. 动态加载配置 (`get_cfg`)

- **`import_module_from_file`**：这是一个关键步骤，它使用 `importlib` **动态导入** 用户指定的 Python 配置文件 (`config.py`)。这意味着配置文件中的所有函数（如 `chn_data()`, `enum_data()`）都会被执行。
- **配置提取与验证**：`get_cfg` 函数从导入的模块中获取名为 **`configs`** 的列表变量。它断言 (`assert`) 列表中的所有元素都必须是 **`GeneratorCfg`** 类型，确保配置格式正确。

### 3. 配置的层次结构

程序获取到一个 **`GeneratorCfg` 列表**，每个 `GeneratorCfg` 包含了完整的生成指令：

| 配置对象 | 核心参数 | 作用 (定义了什么) |
| :--- | :--- | :--- |
| **`GeneratorCfg`** | `num_image`, `save_dir`, `render_cfg` | **批量控制：** 生成多少张图片，保存在哪个目录。 |
| **`RenderCfg`** | `corpus`, `effects`, `layout`, `height`, `gray` | **渲染细节：** 如何生成一张图片（字体、背景、效果、布局）。 |

---

## 三、 并发生成与存储阶段（`main.py` 循环）

程序开始循环遍历加载的 `GeneratorCfg` 列表，对每个配置进行串行处理，但在内部使用并发：

### 1. 串行处理配置

对于每个 `generator_cfg`：

-   **启动消费者**：创建一个 `DBWriterProcess` 实例并 `start()` 启动它。此进程开始等待 `data_queue` 中的数据。
-   **启动生产者**：创建 `mp.Pool` (进程池)，启动 N 个工作进程。

### 2. 生产者进程初始化 (`process_setup`)

这是保证数据集多样性的关键步骤：

-   **进程隔离**：`mp.Pool` 使用 `initializer=process_setup` 确保每个子进程启动时都会独立执行此函数。
-   **随机化**：调用 `np.random.seed()` (无参数) 为当前进程的 NumPy 随机数生成器设置一个**独立**的随机种子。这保证了每个进程的随机数序列不同，避免图片重复。
-   **创建渲染器**：创建独立的 `Render(generator_cfg.render_cfg)` 实例，并赋值给全局变量 `render`。

### 3. 图像生成 (`generate_img`)

-   进程池异步提交 `generator_cfg.num_image` 次任务到 `generate_img` 函数。
-   在每个任务中，调用 **`data = render()`** (`Render` 实例的 `__call__` 方法) 生成图像和标签。
-   将结果打包成字典 `{"image": ..., "label": ...}`，并通过 `data_queue.put()` 发送给消费者。

### 4. 消费者存储 (`DBWriterProcess.run`)

-   进程持续从 `data_queue.get()` 中取出字典。
-   调用 `db.write()` (写入 LMDB 或本地文件) 将图像和标签持久化到磁盘。
-   实时更新进度日志和生成计数。

### 5. 任务收尾

-   当所有生成任务完成后，主进程调用 `pool.close()` 和 `pool.join()` 等待所有生产者完成。
-   主进程发送 `STOP_TOKEN` 到 `data_queue`。
-   消费者进程收到 `STOP_TOKEN` 后，结束循环，调用 `db.write_count()` 更新总数，然后 `join()` 退出。

## 四、 核心渲染流水线（`Render.__call__`）

`Render` 对象执行图像生成时的内部逻辑：

1.  **分流**：调用 `_should_apply_layout()` 判断是走 **单语料** (`gen_single_corpus`) 还是 **多语料** (`gen_multi_corpus`) 流程。
2.  **内容生成**：从语料中采样文本，并获取背景图。
3.  **渲染**：渲染初始文本掩码，并确定文本颜色。
4.  **效果应用 (1)**：应用 **`corpus_effects`** (如文字缺失、描边)。
5.  **布局 (多语料)**：如果多语料，应用 **`Layout`** (如同行、多行) 计算文本位置并合并掩码。
6.  **效果应用 (2)**：应用 **`layout_effects`** (作用于合并后的文本)。
7.  **变换**：应用 **`perspective_transform`** (透视扭曲)。
8.  **粘贴**：将最终的文本掩码随机粘贴到背景图上。
9.  **效果应用 (3)**：应用 **`render_effects`** (作用于最终图像，如噪声、模糊)。
10. **归一化**：转换为 NumPy 数组，进行颜色空间转换 (RGB -> BGR)，并进行 **灰度/高度归一化**。
11. **输出**：返回最终的 NumPy 图像和标签字符串。

## Text Renderer 项目结构与开发逻辑梳理

### 核心设计思想：解耦和流水线化

整个项目围绕“从文本到带特效的图像”的流水线进行设计，将不同的功能（文本、字体、背景、效果、布局、输出）划分到不同的模块中，实现了高内聚、低耦合。

### 一、 核心功能模块

| 模块名 | 关键文件 | 开发逻辑与作用 |
| :--- | :--- | :--- |
| **`config`** | `__init__.py` | **项目的大脑，配置定义**。定义了 `GeneratorCfg`、`RenderCfg` 等数据结构，是用户配置和程序指令的统一接口。 |
| **`corpus`** | `char_corpus.py`, `enum_corpus.py`, `rand_corpus.py`, `word_corpus.py`, `corpus.py` | **文本内容的生产者**。定义了各种文本内容获取和采样逻辑。开发者可以在此添加新的语料类型（如从 JSON 或 XML 格式读取文本）。 |
| **`effect`** | `base_effect.py`, `albumentations_effect.py`, `line.py`, `dropout_*.py`, `selector.py`, `text_border.py` | **图像增强的工具箱**。定义了效果的基础接口 (`Effect` / `Effects`)，以及各种具体的图像变换逻辑（如模糊、噪声、线条、描边）。开发者可以在此添加新的图像增强效果。 |
| **`layout`** | `layout.py`, `same_line.py`, `extra_text_line.py` | **文本排版和定位**。定义了多语料渲染时的文本位置计算和合并逻辑。开发者可以在此添加新的排版方式（如垂直堆叠、环形布局等）。 |

### 二、 核心执行与管理模块

| 模块名 | 关键文件 | 开发逻辑与作用 |
| :--- | :--- | :--- |
| **`render.py` (在 `utils` 目录)** | `render.py` | **中央渲染引擎**。包含 `Render` 类，实现了从配置到最终图像输出的**完整流水线控制**，调度 `corpus`、`effect`、`layout` 等模块协同工作。 |
| **`utils`** | `bg_manager.py`, `font_manager.py`, `dataset.py` | **底层资源管理和工具**。负责加载和管理字体、背景图等资源，以及数据集的 I/O 操作。 |

### 三、 项目执行流程（开发逻辑视角）

| 阶段 | 逻辑流向 | 关键模块和操作 | 目的 |
| :--- | :--- | :--- | :--- |
| **1. 配置定义** | **`config`** $\rightarrow$ 用户文件 | 开发者定义 `RenderCfg` 和 `GeneratorCfg`。决定了**“生成什么”**和**“如何生成”**。 |
| **2. 资源管理** | `utils/font_manager.py` $\rightarrow$ `utils/bg_manager.py` | 在 `Render` 初始化时，加载和缓存字体、背景图，为后续渲染做准备。 |
| **3. 内容生成** | `corpus/*.py` $\rightarrow$ `render.py` | `Render` 调用 `corpus.sample()` 获取文本内容、字体和大小。 |
| **4. 图像渲染** | `render.py` $\rightarrow$ `utils/draw_utils` | **文本掩码绘制**：将文本渲染到一张透明图上（Text Mask）。 |
| **5. 效果应用** | `effect/*.py` $\rightarrow$ `render.py` | `Render` 在三个阶段调用 `Effects.apply_effects()`：<br> - **`corpus_effects`**: 处理单个文本掩码。<br> - **`layout_effects`**: 处理合并后的文本掩码。<br> - **`render_effects`**: 处理最终图像。 |
| **6. 布局处理** | `layout/*.py` $\rightarrow$ `render.py` | `Render` 调用 `self.layout()` 来计算和合并多段文本的位置，得到最终的文本掩码。 |
| **7. 图像合成** | `render.py` | **透视变换** $\rightarrow$ **随机粘贴**：将变换后的文本掩码随机地、透明地粘贴到背景图上。 |
| **8. 输出处理** | `render.py` $\rightarrow$ `utils/dataset.py` | `Render` 进行灰度/缩放归一化，将 NumPy 图像返回给 `main.py` 的**生产者**进程，最终由 **`dataset.py`** (通过 `DBWriterProcess`) 完成存储。 |

这个结构图表明，任何功能的扩展（如添加新的排版、新的效果、新的语料来源）都只需要修改相应的模块，而不会影响到核心的 `render.py` 控制流程。
